System Capabilities

Engineered for Transparency, Speed, and Accountability

Every ticket is managed with deterministic DAA algorithms, providing students and administration with an incorruptible campus grievance ledger.

Handcrafted C Merge Sort

Manual divide-and-conquer implementation in pure C with deterministic multi-level tie-breaking (Priority → Submission Timestamp → Unique ID). Guaranteed O(n log n) efficiency.

Max-Heap Priority Queue

Critical emergencies bubble to root in O(1) peek time. Extracted in O(log n) order using Floyd’s linear O(n) bottom-up heap construction.

Iterative Binary Search

Instantaneous O(log n) complaint lookups across thousands of records. Validated against linear scans to guarantee sub-microsecond retrieval.

Cryptographic Security

Iterated salted SHA-256 key stretching, Windows CryptGenRandom token entropy, and strict HttpOnly SameSite session isolation.

SQLite Audit History Trail

Every status change and priority alteration is transactionally recorded with the updater's identity, timestamps, and administrative remarks.

Live Dynamic Dashboards

Real SQL aggregates dynamically rendered via Chart.js into category breakdowns, status doughnut charts, and one-click authorized CSV exports.

Lifecycle Protocol

Transparent End-to-End Complaint Journey

From initial report to verified facility resolution, every step is logged and trackable.

01

Student Submission

Student submits facility issue with category, room number, description, and suggested priority. System generates unique ID e.g. CMP-2026-0001.

02

Max-Heap Scheduling

C backend Max-Heap priority queue automatically schedules critical infrastructure and water/power emergencies before routine requests.

03

Triage & Maintenance

Campus administration updates status to 'In Progress', assigns maintenance staff, and records transactional administrative remarks.

04

Verified Resolution

Work is marked 'Resolved' with timestamps. The student can inspect the complete timeline and review administrative verification notes.
